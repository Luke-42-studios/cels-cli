    **1a. Create `tools/cels-cli/CMakeLists.txt`:**

    ```cmake
    # cels-cli -- CELS project management TUI
    cmake_minimum_required(VERSION 3.21)

    add_executable(cels-cli src/main.c)

    set_target_properties(cels-cli PROPERTIES
        C_STANDARD 99
        C_STANDARD_REQUIRED ON
        C_EXTENSIONS OFF
    )

    target_link_libraries(cels-cli PRIVATE
        cels
        cels-ncurses
        flecs::flecs_static
    )

    # Access shared component definitions from examples/
    target_include_directories(cels-cli PRIVATE
        ${CMAKE_SOURCE_DIR}/examples
    )
    ```

    Uses `add_subdirectory` from the root -- `cels`, `cels-ncurses`, and
    `flecs::flecs_static` targets are already available. The `examples/`

    if(CELS_BUILD_TOOLS)

        add_subdirectory(tools/cels-cli)

    Create `tools/cels-cli/src/main.c` as a single-file CELS ncurses app
    following the `examples/app.c` architecture exactly.

    The app structure mirrors app.c:
    - `CEL_State(CliState, { CliTab active_tab; })` for tab tracking
    - `CEL_Composition(TabRouter)` watches CliState and routes to tab compositions
    - 4 tab compositions with placeholder text using Canvas + Text components
    - `CEL_System(CliInputSystem)` reads CELS_Input for tab switching
    - `CEL_Root(AppUI, TUI_EngineContext)` waits for window ready, mounts router
    - `CEL_Build(App)` calls `TUI_Engine_use(...)` and init functions

    **Architecture overview:**

    ```
    CEL_Build(App)
      -> TUI_Engine_use(.title="cels-cli", .fps=30, .root=AppUI)
      -> InitConfig()

    CEL_Root(AppUI, TUI_EngineContext)
      -> CEL_WatchId(ctx.windowState) for window ready
      -> CEL_Init(TabBar) {}
      -> CEL_Init(TabRouter) {}
      -> CEL_Init(StatusBar) {}

    CEL_Composition(TabRouter)
      -> CEL_Watch(CliState) to get active tab
      -> switch() to instantiate the correct tab composition

    CEL_Composition(ProjectsTab) / PackagesTab / BuildTab / TestsTab
      -> Placeholder: CEL_Has(Text, .content = "tab name")

    CEL_System(CliInputSystem)
      -> Reads CELS_Input for 1-4 number keys, Tab key
      -> CEL_Update(CliState) to switch tabs
    ```

    **Key implementation details:**

    1. Check `CELS_Input` struct in `cels.h` for actual field names.
       The TUI input provider maps ncurses key codes to these fields.
       If the struct doesn't have `key_number` or `key_tab`, look at
       how `examples/app.c` reads input (it uses `axis_left`, `button_accept`,
       etc.) and map number keys through the input provider.

    2. Tab bar rendering: Use the `Text` component from `components.h`
       positioned at the top of the screen. Active tab gets highlighted
       via a different component value or a render system that checks
       CliState.active_tab.

    3. Status bar: A composition at the bottom that uses `Text` with
       `getcwd()` for the current directory and "cels-cli v0.1.0".

    4. Each tab composition only needs placeholder text for Phase 1.
       Example: "No projects found. Press Enter to create one."

    5. The render provider from `render_provider.h` in `examples/` handles
       drawing Text, Canvas, Selectable, etc. to the ncurses window.
       Call `app_renderer_init()` in CEL_Build to register it.

    6. If `app_renderer_init()` from examples isn't appropriate for the CLI
       (it may reference demo-specific features), create a minimal
       `cli_renderer_init()` that registers only the Text rendering provider.
       Or use the feature/provider system directly.

    7. The q-to-quit key is handled by the TUI_Engine input provider
       automatically -- it maps 'q' to the quit signal. Verify this
       is the case; if not, the input system should check for 'q'.
  </action>
